## 复审意见的处理（0.2.11）

按你“存档和调试一起改”的决定，复审意见除了下面注明不改的，都改了。改之前先查了反编译代码：存档后台任务（`SaveDataUtility._runningSaveTask` / `_saveTaskQueue`）、恢复点的来源和删除规则、`PlayerData` 里不进存档的复活点字段、`AchievementHandler` 的排队和发放、`Platform.IsSaveSlotIndexValid`、长椅 FSM 坐下时会存档。

| 意见 | 处理 |
|---|---|
| 只换了一个数据对象 / 控制器还在大厅 | `SwapIn`：两个都换了 = 别的存档，快照作废，照常存；只换了一个、或者槽对不上 = 拦下这次存档（回调 false，横幅提示）。嵌套调用要求 GameManager 上还是换进去的那两个对象；`SwapOut` 只在对象没被换掉时才换回。模式开着（离开途中除外）却发现快照没了或对象换了，整体重置模式 |
| 离开途中的存档 / 死亡 | 去掉了切场景的 Finalizer。“不保存场景状态”从还原快照开始一直保持到回到原来的长椅，到了才放开；到了别的场景就再走一次（最多 3 次）。离开途中死亡在原来的长椅醒来，不回大厅 |
| 进入前的存档还没写完 | 开战前如果游戏还有没写完的存档，先不开战（横幅“正在存档”，自检会等它写完）。进入本身没加限制：正常进入要坐长椅，坐下时游戏刚存完档，离开战前还有几秒 |
| **恢复点** | 有快照期间不生成恢复点：`CreateRestorePoint` 直接按成功回调；`SaveGame` 的“顺带恢复点”参数改成 false。全量自检里实际拦下的是后一种（4 次），`Restore_Points4` 前后 20 个文件名字、哈希、时间完全一样 |
| 调试模式下进入前没存的进度 | **没改**。只在调试模式下发生（正常进入要坐长椅，坐下时刚存过档） |
| 嵌套切场景 | 随着去掉 Finalizer 一起解决 |
| 调试才列出的 Boss、F6 放弃 | 改成同时检查“调试开着 + 当前槽在白名单里” |
| 自检中途被关掉 | 每轮自检有编号，开新的一轮先停掉旧的；中途不允许了就原地中止，不再回大厅、不离开；只有没中止才离开；退出游戏前核对编号 |
| 把“状态 = Off”当成存档写完 | 离开后那次存档的结果带回给自检，要等到“成功”才算完成、才退出游戏 |
| 组件被禁用、心跳超时 | 禁用和销毁都停掉自检、恢复无敌；心跳改成按帧数（600 帧），超时停掉协程并换编号 |
| 离开时清空复活点 | 进入时记下临时 / 非致命复活点，离开时恢复成进入时的值 |
| 延后执行的场景调整步骤 | 每场战斗有编号，每次等待后核对，过期就不再执行 |
| 还原核对不一致也放快照 | 不一致或核对出错就不放快照、留在圣所里，横幅提示从暂停菜单回标题再读档 |
| 嵌套存档期间换对象 | 见第一条 |
| 延后发放的成就 | 查了：成就是先排队、`AwardQueuedAchievements` 发放后清空队列。模式里排队本来就被拦；现在发放也整个推迟到离开以后（原来会把进入前排队的成就清掉） |
| 离开战场时的胜利判定 | 图鉴判定改成战斗中和离开时同一个；血量判定只用在没有击败标记的 Boss 上，离开时不等宽限期（人已经走了，没法再等） |
| `allowScenes` 场景被排除 | 算进这场战斗的场景 |
| 尝试次数 | 不在开战时记，一场结束（赢、死、放弃）时记一次；调试辅助的场次不记、也不建空记录；大厅里就开着无敌时开战就算辅助 |
