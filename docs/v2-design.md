## 整体结构

```
新建存档 → 选“织忆圣所”
  └→ 出生在【织忆圣所】：长椅（换装）、织忆之机（灵丝织球）、古织者像、通往长廊的丝门
       └→ 丝门传送 →【忆像长廊】：上下两层，每个 Boss 一尊雕像，按幕排列；丝线升降和右端台阶连接两层
            └→ 在雕像前交互 → 选难度：素织 / 重织 / 断丝
                 └→ 从 door_dreamEnter 进原场景的神居版开战（见 docs/arena.md）
                      └→ 赢或倒下 → 回到这尊雕像前，雕像上记下通过了哪一档
       └→【万神殿】的门先留着，不开（以后做）
```

### 没有剧情阻碍

- 每场战斗开打前，按 Boss 表里的 `prerequisites` 临时设好条件，比如“某个剧情做到哪了”、`blackThreadWorld`。
- 开打时跳过开场对话：开战前设好“见过”标记走重打分支，需要的再加加载时补丁（`arena.encountered`、`arena.patch`）。
- 打完用第一版已经验证过的快照还原。神居存档里的世界状态永远不变，战绩另外记。
- 打完不弹获得提示（2026-11-26 加，0.10.1 玩家反馈打完幽影弹“获得十字绣”）：神居模式里技能（`SkillGetMsg`）、能力（`PowerUpGetMsg`）、纹章（`ToolCrestUIMsg`）、
  物品（`CreateUIMsgGetItem`）的获得提示都不弹（`Patches/RewardMsgPatches.cs`），下一帧照提示关掉时那样调回调、补发事件（例如幽影的 `SKILL GET MSG FADED OUT` / `ENDED`）。
  满配已经都有了，快照还原后这些奖励本来也不会留下。
- 战斗中 HUD 收着就叫回来（2026-11-26 加，0.10.1 玩家反馈原初罪者整场没血条）：开战以后 HUD 收着、人又能操作（没交出控制、没死），连续 2 秒就叫回来（`ModeController.CheckFightHud`）。
  跳过开场时可能跳过了原版叫回 HUD 的那一步（原初罪者的神龛在 Look Back 收了 HUD，后面没有地方再叫）。开场演出、对话会收回控制，不受影响。
- 切磋战（沙克拉、加蒙德、针姬）跳过对话时，要让对话 NPC 的 FSM 走到原版“答应切磋以后”的状态，不能只给 Boss 发开打的事件（2026-11-26，0.10.1 玩家反馈“中途变回对话模式”、针姬隐身）：
  对话 FSM 停在等对话的状态会一直开着交互提示、NPC 的看人动画，还会对唱歌、噪音做反应（对 Boss 播 NPC 的动画）；有的 Boss 本体渲染要靠 NPC 醒来的那一步打开。每场的做法写在 `data/bosses.json` 的 `arena.$comment` 里。
- 第一版的“只列出打过的 Boss”这道护栏，在神居存档里不存在：雕像全部可以挑战。

### 存档安全（第二版）

- 神居存档只会建在你选的**空槽**上，普通存档完全不碰。
- 不写全局状态记录（见上面“不写状态记录”）。
- 神居存档里不发成就。成就是你 Steam 账号上的，满配打 Boss 不该替你解锁。
- 第二版的插件只在 `bossRushMode = true` 的存档里做事。普通存档读进来以后，插件什么都不改。
- 神居存档里，从圣所走出去、进到不是战斗场地的地方，都会被改道回圣所。满配大黄蜂不能跑进真实世界。

## 第二版的存档模型

第一版的快照是“整段模式”一份：进圣所时拍，离开时还原。

第二版没有“离开”，改成**每场战斗一份**：

- **圣所里**：不换数据，存档照常写实时数据。所以在长椅上换的纹章、工具会被正常存下来。
- **开战前**（传送出去的那一刻）：给圣所里的状态拍快照。这一刻也要等游戏手上的存档任务做完，第一版已经有这道闸门。
- **战斗中**：游戏存档时写进去的是快照，沿用第一版的 `SwapIn` / `SwapOut`。这期间崩溃或者强退，读档会回到开战前的圣所。
- **回到圣所**：把快照逐字段拷回实时数据（沿用第一版的 `RestoreAndClear` 和核对），然后丢掉快照。

战斗里发生的一切（击败标记、图鉴、剧情变量、拿到的东西）都不会留在神居存档里。战绩照旧通过 DataManager 按槽另存。

## 风险 / 待实机确认

- 隐藏按钮亮出来以后，菜单上下导航要自己接好（原来 `GGButton` 往上接“普通”，往下接“确定”）。
- 满配后，有些剧情物品或任务物品可能会让雕像房间、对话出现意外内容，阶段 1 实测。
- 全部场景的 PlayMaker 里有没有用到前作的 `GGCheckIsBossRushMode`：目前只解包过 30 个场景，没看到。阶段 1 会把 590 个场景全扫一遍。
- B / C 做法的长廊：镜头边界要靠改地块图尺寸，或者在 `RefreshTilemapInfo` 之后改 `sceneWidth` / `sceneHeight`，阶段 2 先做一个小样验证。
