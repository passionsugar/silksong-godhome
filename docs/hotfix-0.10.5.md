# 0.10.5 本地修复候选：丝母战后悬浮、神居资源与双苔母入口

基于上游 0.10.4，提交 `de3e4d70e172454d626ec43241bb23721e351bff`。这是本次问题排查生成的本地修复候选，未上传 GitHub、未发布 Thunderstore。版本号用于区分旧 DLL，不表示上游作者已经发布或确认。

## 适用范围和验证边界

针对三项报告：丝母战后不自然下降、连续跳跃上升；神居的念珠炮和建筑师缺念珠/工具碎片；双苔母偶发落在地图外。

编译接口以项目锁定的 `Silksong.GameLibs 1.2.0-silksong1.0.30000` 为准。参考程序集没有可执行的游戏方法和真实场景地形。本次没有启动《丝之歌》或 Unity，不能把编译通过、隔离测试通过当成游戏内验证。也没有收到描述中提到的截图、出错存档或当时日志，因此“丝母结局状态泄漏”是代码与症状吻合的根因判断，不是对玩家当时内存状态的直接观测。

## 1. 丝母打完后浮空

### 原代码的问题

丝母的判胜入口是 `Boss Scene/Silk Boss` → `Phase Control` → `Death Hit`。旧的 `Arena.InsertEnd` 在原动作数组前插入 `EndGGBossScene`，随后仍然会运行原动作和状态跳转。神居判胜并不自动停止原版结局。

保存快照主要恢复 `PlayerData` 和 `SceneData`，并不恢复持久角色控制器的重力、刚体与控制状态。如果结局流程改变这些状态，再由神居提前离场，就可能把剧情状态带到后续场景。无自然下降、仍能主动攻击或冲刺，与单纯掉帧或整个输入系统失效并不相同。能否确认当时具体哪个字段异常，仍需现场日志或复现。

### 修复

- 为 `arena.end` 增加严格布尔字段 `terminal`，默认关闭；仅丝母的最终 `Death Hit` 启用。
- 该终点只执行神居判胜动作，阻止原状态继续通向结局；进入终点时才封住该 FSM 的全局跳转，不提前破坏 Boss 战斗阶段。
- 不停止场地控制器，保留原有判胜、完成回调及转场流程。
- 在旧战场离场的安全边界调用游戏原生 `AffectedByGravity(true)` 和 `ResetGravity()` 恢复重力，再核对实际开关和数值。不同字段的单位与缓存由原生方法处理，不写死重力常数；原生恢复后仍异常就记录警告，不假称恢复成功。
- 终止原结局也可能略过其中的攻击清理，因此增加仅对当前终止结局、已判胜 `Won` 状态生效的伤害保护。不会给存档写无敌标记，离开 `Won` 即失效，也不逆转已发生的死亡或最后一击前的伤害。
- 清理神居里残留的剧情无限空跳标记；普通模式不处理。大厅补偿恢复受角色、存档、场次和运动状态约束，避免抢走正常技能、长椅或过场控制。
- 不在每帧强制重力，不在下一场 Boss 已经开始执行开场演出后强制解锁控制。

## 2. 神居念珠和工具碎片无限使用

神居战斗关闭一般拾取物，但原有满配表没有补念珠和工具碎片。持有工具与具有使用工具所需的资源是两回事。

修复补足真实 `PlayerData.geo` / `ShellShards` 字段到至少 **9999**，让直接读取字段的可用性检查也能通过。现有更高余额保留。对这两类资源的正常消费入口，将正向扣款改为 0，继续执行原方法；查询余额时也补足。通用 `GetInt` / `SetInt` / `IntAdd` / `DecrementInt` 仅对这两个字段补给，模式更新另做两次数值比较，覆盖直接字段写入。不是给一次 9999 后照常扣完，也不使用 `int.MaxValue`，界面不另绘制“∞”符号。

生效条件是当前实时对象确属神居存档，而且 `GameManager.playerData` 与 `PlayerData.instance` 为同一对象。普通存档、已经离开的旧对象和保存时临时替换的快照不享受补给。0 或负数金额保留原有语义。

仅供给念珠和工具碎片，不改变灵丝、普通工具弹药或工具束缚。需要验证念珠炮及建筑师在游戏中的实际消费路径；隔离测试不能证明第三方模组对这些路径的改写也兼容。

## 3. 双苔母出生在地图外

原始门锚点为 `Weave_03` 的 `(1.7, 29.9)`。门型入场会从指定 X 向下找地面，而原来的入场确认只核对门名，无法证明角色身体已经位于场内。不能仅凭这个坐标和一次报告，断言地图哪一堵墙的位置，也不能凭空换成另一组坐标。

修复仅对 `moss_mother_duo` / `Weave_03` 启用：在角色就位后的物理帧、补发开战触发前，使用配置中明确的 `Boss Scene` / `BattleScene` 触发区域核对实际落点，并检查角色体积、障碍与脚下地面。落点无效时，仅在该区域内有限寻找安全站立位置，修正一次并同步危险复活点；确认不了安全位置则回大厅，记录场地错误，不留玩家在图外。

区域取自该场景实际触发器形状。触发器可能在首次入场后已关闭，因此不能只用禁用后为空的 `Collider.bounds`。不启用原触发器、不任意挑选邻近的其他战斗、不在战斗中每帧传送玩家。

这项修复需要真实 `Weave_03` 地形验证，尤其要检查入口选择、双 Boss 是否同时激活、墙体关闭和掉坑复活。无法识别或无法证明安全的几何会导致安全返回大厅，而不是继续不可靠入场。

## 更新已有安装

1. 完全退出游戏。
2. 在当前实际使用的 `BepInEx/plugins` 中找到旧 `Godhome.dll` 所在的整个模组目录，将它移出插件目录作为备份。目录可能叫 `Godhome`、`local-Godhome`，或由管理器命名。不要把两个版本一起留在 plugins 内。
3. 将更新包里的 `BepInEx/plugins/Godhome` 放进这个 plugins 目录。必须同时更新 DLL 和旁边的 `data`、`languages`，因为丝母的终止配置在 `data/bosses.json`。
4. 使用 r2modman 等管理器时，更新当前配置文件的 plugins 目录；不要误装到未启用的另一份游戏目录。
5. 保留现有 BepInEx、DataManager、I18N 和可选的 UnitySceneRepacker。这个更新包不携带游戏程序集，也不替换这些依赖。
6. 重新启动后检查 `BepInEx/LogOutput.log` 的加载版本为 `Godhome 0.10.5`，再读取原来的神居存档。不要求删除存档或新开档。

已经出现的浮空状态不应靠不断跳跃处理。完成更新并完全重启游戏，再载入神居，能让新的控制器初始化和修复逻辑生效。若仍有异常，保留当次日志，记录是在丝母原场景、回大厅后、还是下一场中发生。

回退时完全退出游戏，将新 `Godhome` 文件夹移走，把备份的旧模组文件夹放回原位。修复没有新增存档结构，不要求迁移存档格式。
